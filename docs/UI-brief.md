Working on it standalone
1. Generate preview data from any finished render:
.venv/Scripts/python -m eluate.uidata "work/<track> - eluate" ui/data.js
2. Open ui/index.html straight in Chrome or Edge. Before/After playback works too, since it reads that render's ab/ files.
3. Add #controls to the URL (index.html#controls) to open with the Controls panel expanded.
The browser shows the finished-render state only. The empty state ("No track"), the preview while rendering, the stage/elapsed text and the error line only appear inside the app. To see those, run cd desktop, then npm run dev (it uses the .venv engine directly). There's no hot reload: each start copies ui/ into the app, so restart it after edits.
What you can change freely
- Colours, type and spacing: everything in :root. The SVG charts use the same CSS variables (fill: var(--ice) and so on), so palette changes carry through to the charts.
- Layout, spacing, borders, button styles, the disclosure chevron, footer, header: all plain CSS.
- Chart text: styled through the classes .tl-axis, .tl-label, .sec-name, .sec-ref, .sec-val (sizes in rem, so they follow the text size). The legends are HTML (.spec-legend, .key) in each view's head row, not SVG.

Constraints inside the desktop app
- CSP: no inline <script> or onclick= attributes, and nothing loaded from the web: no Google Fonts or CDNs. Fonts and images must sit in ui/, and images can also be inline data: URIs. Inline style="" attributes are allowed.
- The brief's GUI text rule: control names, live values, must-know state and navigation only. No taglines, hints or explanatory copy.
- Window size: opens at 1440×980, minimum 960×640. There's also a layout below 900 px wide, mostly irrelevant in the app. The Controls body and the track list re-flow on their own width in rem (container queries on .controls and .list: one column under 70rem, the narrow row layout under 56rem), so they also re-flow at a large text size. The transport wraps: the stats take a row of their own when they don't fit beside the player, and drop their before values below 1240 px.

Progress, lock-out and Cancel (maintainer feedback 2026-10-24: "it starts analysing immediately ... no estimate ... no lock out ... or cancel button")
- The status in the track row (`#stage`, under the name) says what the engine does in plain words: "Reading track" while a track loads (the preview: the file read and the before graphs, no analysis), then "Analysing" while its analysis runs in the background (the analysis the render needs, cached so Render does not repeat it), then "Ready"; during a render "Step 1 of 4: Analysing", "Step 2 of 4: Planning", "Step 3 of 4: Mastering · render 2 of up to 7", "Step 4 of 4: Writing report", "Loading graphs", then "Done". `#stage-text` is the live region (role status), announced when the stage changes; an error is shown in `#stage-err` beside it (red, aria-hidden) and announced once by `#stage-alert` (sr-only, role alert), with the engine's raw text in `#stage`'s title. `#stage-time` beside it is the engine's estimate counted down ("about 6 min left", "under a minute left"), or the elapsed time when there is none ("7:42 elapsed"), and is not announced. `.stage.running` keeps the spinner and lights the text.
- Cancel (`#cancel`, a `.ghost` button at the right of the track row) shows while a render runs or the selected track is being analysed; it stops the render (or the queue) and the analysis. The stopped track goes back to Queued (a Done track too once its re-render had started: the engine clears the completion marker first). Render stays Render and is disabled while a render runs; focus moves to Cancel when Render is pressed, back to Render after.
- While a render runs (or the analysis it waits for), the settings it renders with are disabled with a visible dimmed state: Tilt, Preserve mix, Tempo, Character, Loudness, Delivery, Profile and the crossover / side high-pass handles. Playback, the graph tabs, the list (selecting rows), Open / Folder / drop (new tracks join the queue; a file already in the list is ignored) and Limit CPU stay usable.

UI audit fixes (2026-11-10, docs/audit-2026-11-10/ui.md findings 1-28)
- Targets are the displayed master's: Tilt's target is the render's `tilt.target`, Loudness's `loudness.target`, in the reached values, the Controls summary, the spectrum and the timeline. The controls only set the next render (Render's `changed`). On the timeline, a Loudness control moved off the master's target is a faint dashed line (`.tl-pending`); before a render the Before curve follows the Loudness slider. Changing Profile redraws the spectrum. The spectrum's amber is the engine's tilt flag, Stereo view only; Mid and Side draw the target without amber.
- Character: beside Tempo the displayed master's timing preset (`character.preset`, the engine's); before a render, Auto's rule (slow only for a tempo the user gave).
- Reopening a mastered folder: while no control was touched and nothing rendered this run, the first Done track's shared controls (Loudness, Tilt, Preserve mix, Delivery, Character, Profile) are adopted. A Done track made with other settings reads "Done · other settings" and is never re-mastered until a control is edited; after an edit a Done track whose settings no longer match reads "Done · settings changed" (status and list), and Render re-masters it. Picking the already-checked radio is no edit.
- Blind A/B: one session per master for the run, so a master whose answer was shown is never voted on again; a master with a vote on disk (`voted`) opens unblinded with no vote buttons. Once the answer is out the Blind switch reads off and is disabled until the next master. A vote that could not be saved says "Vote not saved." and is not shared.
- Footer stats (values only, absent rows left out for older renders): Integrated (LUFS, before small), True peak (amber from the tp flag), Crest, Range, Noise, Playback (Spotify and Apple gain, dB), Format (rate, bits, dither; ceiling small), Flags n. Flags n is a button (`#flags-btn`, amber when n > 0) that opens `#flag-list` above the transport: the engine's own text for every short flag, of every kind. Escape closes it.
- Errors: the status shows plain words for common cases (File not found, Can't write next to the file, Disk full, Not enough memory, Can't read this audio file, Engine stopped unexpectedly), the raw text in the status and row tooltips. A stem set's null test shows after its sum ("Ready · null −62 dB", "· no mix").
- Accessibility: the spectrum's svg is a group (its drawing aria-hidden) so the crossover and side high-pass sliders are reachable; the consent panel returns focus and closes on Escape; list options carry an aria-label (name, state, values with units, flag count) and the 1 s tick only rewrites the `.st` cells; the timeline slider's valuetext reads the levels on keyboard seek; `.targets` and `.character` are role group. Non-text contrast: slider tracks, the number field border and the crossover lines are graphite (5.07:1); the target line has a steel halo (11.7:1 against the After fill).
- Behaviour: arrow keys in the list start the selected track's view job once the keys stop (250 ms); a crossover drag uses pointer capture and re-runs the track's analysis when it ends; Delete twice on a rendering row removes one track; re-picking a stem set that is summing or rendering only selects it; eluate-batch.csv quotes cells starting = + - @ as text and adds Integrated (LUFS) and Character columns.
